# Flaggr Provider

The Flaggr provider manages [Flaggr](https://flaggr.dev) as code: organizations and their members, projects, environments, services, feature flags, alert channels and rules, and metric sources. Flaggr is an OpenFeature-compatible feature flag platform; see the [Flaggr documentation](https://flaggr.dev/docs) and the [infrastructure-as-code guide](https://flaggr.dev/docs/guides/infrastructure-as-code).

## Example Usage

```terraform
terraform {
  required_providers {
    flaggr = {
      source  = "flaggr-dev/flaggr"
      version = "~> 0.1"
    }
  }
}

# Both arguments are optional: the provider falls back to the FLAGGR_API_URL
# and FLAGGR_API_TOKEN environment variables.
provider "flaggr" {
  api_url   = "https://flaggr.dev" # the default
  api_token = var.flaggr_api_token
}

variable "flaggr_api_token" {
  description = "Flaggr personal access token (fgp_…, recommended) or project API token (fgr_…)"
  type        = string
  sensitive   = true
}
```

## Authentication

The provider sends a Flaggr API token to the Flaggr API (`https://flaggr.dev` unless you set `api_url`). Set it with the `FLAGGR_API_TOKEN` environment variable (recommended) or the `api_token` argument.

- A **personal access token** (`fgp_…`, recommended) acts as you in every project and organization you can access, limited to the tier you chose when you created it; your own roles still apply. Create one in Flaggr under [**Profile → Personal access tokens**](https://flaggr.dev/console/profile#personal-access-tokens).
- A **project API token** (`fgr_…`) works only for resources inside its own project: it can't create or delete projects, change a project's slug, or manage organizations and their members.

| What Terraform manages | Personal access token you need |
|------------------------|--------------------------------|
| Services, flags, alert channels and rules, metric sources in existing projects | **Write** tier |
| Organizations, organization members, environments, and creating or changing projects | **Admin** tier |
| Deleting projects or organizations (`terraform destroy`, or removing a `flaggr_project` or `flaggr_organization`) | **Admin** tier with **Allow owner actions**, and you must be an owner |

Without **Allow owner actions**, deleting a project or organization fails with HTTP 403: remove the resource from state with `terraform state rm` and delete it in the Flaggr dashboard instead. Tokens expire after 7, 30, 90, 180 or 365 days; rotate them on the same page.

The provider identifies itself as `terraform-provider-flaggr/<version>`, so the token's **Last used** column in Flaggr shows Terraform.

### Secrets in `config`

Flaggr returns the secrets inside `flaggr_alert_channel` and `flaggr_metric_source` `config` (API keys, tokens, webhook URLs, header values) only to admin-tier tokens. Below the admin tier they read back as `"[redacted]"`. The provider keeps the values from your configuration in state, so this causes no diff, but it can't see a secret changed outside Terraform: use an admin-tier token to detect that drift. Pass secrets in from sensitive variables, and don't write `"[redacted]"` in `config` yourself.

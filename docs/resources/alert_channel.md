# flaggr_alert_channel (Resource)

Manages a Flaggr alert notification channel. Alert rules (`flaggr_alert_rule`) notify the channels they list.

## Example Usage

```terraform
variable "slack_webhook_url" {
  type      = string
  sensitive = true
}

variable "pagerduty_routing_key" {
  type      = string
  sensitive = true
}

variable "alert_webhook_secret" {
  type      = string
  sensitive = true
}

resource "flaggr_alert_channel" "slack_ops" {
  project_id = flaggr_project.platform.id
  name       = "Ops Slack"
  type       = "slack"
  enabled    = true
  config = jsonencode({
    webhookUrl = var.slack_webhook_url
  })
}

resource "flaggr_alert_channel" "pagerduty" {
  project_id = flaggr_project.platform.id
  name       = "On-Call PagerDuty"
  type       = "pagerduty"
  config = jsonencode({
    routingKey = var.pagerduty_routing_key
  })
}

resource "flaggr_alert_channel" "email" {
  project_id = flaggr_project.platform.id
  name       = "Release Managers"
  type       = "email"
  config = jsonencode({
    recipients = ["releases@example.com"]
  })
}

resource "flaggr_alert_channel" "webhook" {
  project_id = flaggr_project.platform.id
  name       = "Custom Webhook"
  type       = "webhook"
  config = jsonencode({
    url    = "https://hooks.example.com/flaggr-alerts"
    secret = var.alert_webhook_secret
  })
}
```

## Channel configuration

`config` is a JSON document (use `jsonencode()`) whose shape depends on `type`:

| `type` | `config` |
|--------|----------|
| `slack` | `{ webhookUrl = string }` |
| `discord` | `{ webhookUrl = string }` |
| `email` | `{ recipients = list(string) }` |
| `pagerduty` | `{ routingKey = string }` |
| `webhook` | `{ url = string, secret = optional(string) }` |

Webhook URLs, signing secrets and routing keys read back as `"[redacted]"` to tokens below the admin tier (see [Secrets in `config`](https://registry.terraform.io/providers/flaggr-dev/flaggr/latest/docs#secrets-in-config)). An imported channel starts with `"[redacted]"` placeholders until the next apply sends your configured secrets. Below the admin tier, Flaggr also refuses (HTTP 403) an update that keeps a `"[redacted]"` placeholder while changing where the secret goes (the channel's URL, recipients or type): put the real secret in `config`, or use an admin-tier token.

## Schema

### Required

- `config` (String, Sensitive) Type-specific configuration as JSON.
- `name` (String) Channel name.
- `project_id` (String) Project ID.
- `type` (String) Channel type (email, slack, discord, pagerduty, webhook).

### Optional

- `enabled` (Boolean) Whether the channel is enabled.

### Read-Only

- `created_at` (String) Creation timestamp.
- `id` (String) Alert channel ID.
- `updated_at` (String) Last update timestamp.

## Import

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = flaggr_alert_channel.slack_ops
  id = "your-project-id:your-channel-id"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Alert channels are imported by "projectId:channelId".
terraform import flaggr_alert_channel.slack_ops "your-project-id:your-channel-id"
```

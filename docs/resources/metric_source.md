# flaggr_metric_source (Resource)

Manages a Flaggr metric source for golden signal monitoring.

## Example Usage

```terraform
resource "flaggr_metric_source" "prometheus" {
  project_id = flaggr_project.platform.id
  name       = "Production Prometheus"
  type       = "prometheus"
  enabled    = true
  config = jsonencode({
    endpoint = "https://prometheus.example.com"
    queries = {
      errorRate  = "sum(rate(http_requests_total{status=~'5..'}[5m]))"
      latencyP99 = "histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m]))"
      throughput = "sum(rate(http_requests_total[5m]))"
    }
  })
}
```

## Source configuration

`config` is a JSON document (use `jsonencode()`) with the settings for the source's `type`. The provider adds `type` to `config` itself, so you don't need to repeat it.

Secrets in `config` read back as `"[redacted]"` to tokens below the admin tier (see [Secrets in `config`](https://registry.terraform.io/providers/flaggr-dev/flaggr/latest/docs#secrets-in-config)). An imported source starts with `"[redacted]"` placeholders until the next apply sends your configured secrets. Below the admin tier, Flaggr also refuses (HTTP 403) an update that keeps a `"[redacted]"` placeholder while changing where the secret goes (the source's `endpoint`, `url`, `site`, `region`, `realm` or `stackSlug`): put the real secret in `config`, or use an admin-tier token.

## Schema

### Required

- `config` (String, Sensitive) Type-specific configuration as JSON (use jsonencode()).
- `name` (String) Metric source name.
- `project_id` (String) Project ID.
- `type` (String) Metric source type (prometheus, datadog, cloudwatch, custom_webhook, internal, signalfx, newrelic, grafana_cloud).

### Optional

- `enabled` (Boolean) Whether the metric source is enabled.

### Read-Only

- `created_at` (String) Creation timestamp.
- `id` (String) Metric source ID.
- `updated_at` (String) Last update timestamp.

## Import

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = flaggr_metric_source.prometheus
  id = "your-project-id:your-source-id"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Metric sources are imported by "projectId:sourceId".
terraform import flaggr_metric_source.prometheus "your-project-id:your-source-id"
```
